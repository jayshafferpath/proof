Skip unrecognized categories — don't throw

Detect the out-of-union value and pass the record over.

instead ofLet it reach the exhaustive switch and throw, or widen the union to accept it
Why it matters

The upstream service emits categories outside our closed union; its generated client surfaces them as an unknown-enum sentinel that adapters cast in blindly. That value hit an exhaustive switch and threw — and since the handler logs-and-rethrows, it became a poison-message retry loop. The upstream team confirmed these records should be ignored.

“We confirmed with the upstream team that these records should be ignored / passed over.”— PR description · Root cause

2✎ author-stated

Guard once in the shared business layer, not per adapter

Put the check in OrderSubscription, which every adapter funnels through.

instead ofValidate in each adapter — queue handlers, the poller, the linked-record fetch
Why it matters

The unsafe cast happens in several adapters, but they all converge on the subscription before business logic runs. One choke point covers every entry point — created, updated, cancelled, fulfilled, refunded — instead of scattering the same validation and missing one.

“OrderSubscription — the single business layer all adapters funnel through — now skips records with an unrecognized category at every entry point.”— PR description · Change
Behaviour it shapes
▸The predicate lives on the subscription and is called from every entry point, so no adapter can bypass it.

3✎ author-stated

Make every skip observable

Warning log plus a new record_skipped_unrecognized_category metric.

instead ofSkip silently
Why it matters

A silent skip and a lost message look identical from outside — and this path exists because an upstream contract is leaking. The metric turns 'we're dropping records' into a rate the team can alarm on and hand back upstream. The skip is a symptom worth watching, not a fix to forget.

“Skips are observable: a warning log + a new record_skipped_unrecognized_category metric.”— PR description · Change
Behaviour it shapes
▸Before returning true, the predicate emits a structured warning and increments a dedicated counter.

4✎ author-stated

Treat an unrecognized LINKED record as absent

Behave as if there is no linked record.

instead ofThrow while building linked-record event properties
Why it matters

Enrichment reads the record's linked sibling. If that record carries a sentinel category, the same switch would throw mid-enrichment — turning an unprocessable neighbour into a failure of the current event. Treating it as absent degrades gracefully: the current event still ships.

5✎ author-stated

Leave the exhaustive switch as an unreachable invariant

Keep categoryLabel's throwing switch untouched.

instead ofAdd a default arm to absorb unknown values
Why it matters

The upstream guard means the switch can no longer be reached with a bad value. Softening it with a default would silently absorb future real bugs; keeping it strict documents the invariant 'everything reaching here is recognized' and still throws loudly if a different path ever breaks that.

“The exhaustive switch in categoryLabel is left as-is (now an unreachable defensive invariant).”— PR description · Change
A deliberate non-change — invisible in the diff.
